Key architectural decisions first
Keep Arc — don't touch it
Arc stays as-is until the slab lands. The iwori_arc_rc_duality spec is superseded by Phase 3. Don't spend time on the toggle.
No WeakList / WeakMap
Drop the proposal entirely. Exposing weak refs as a language primitive leaks the runtime model onto the user.
GPU slab is the reference impl
gpu.rs:821–1004 already has size classes, free bitmaps, and stats. The CPU slab is a parameterisation of that, not a rewrite.
GC is a target backend param
The GC strategy is not a language decision. It lives in target-specific backends. ifa-types only knows about indices.
Cycle collection gap: the current Arc-based model leaks on cycles and has no collector. Phases 0–1 do not fix this — they lay the foundation. Bacon-Rajan trial deletion (Phase 2) is the first real fix. Don't ship graph-heavy workloads as stable until Phase 2 lands.

Phase 1 Wire IfaValue heap variants to slab indices Breaking change — coordinate with ifa-vm
1.1
Replace Arc<List>, Arc<Map>, Arc<Str> with u32 slab indices in IfaValue
The index is the portable handle. How it gets freed is the target-specific backend's concern. This is the load-bearing change that makes IfaValue: Copy + Send + Sync trivially.
ifa-types
1.2
Introduce per-actor OponSlab backed by SlabAllocator<RamBackend>
Each actor owns one OponSlab. The actor's stack and heap are index ranges within it. The Opon flight recorder now also serves as the root set for GC.
ifa-vm
1.3
Update Osa.ran message passing to use index handoff + deferred free
On yanda, the sender passes the index and enqueues a deferred-free message back to itself. SysRuntime in ifa-infra provides the channel: async on native/tokio, synchronous on WASM/embedded.
ifa-vm
1.4
Unlock Rayon parallelism in cpu.rs
Remove the sequential fallback comments at cpu.rs:507 and :525. Add index-range partitioning to ensure parallel workers operate on disjoint slab regions — this is a hard constraint, not optional.
ifa-infra
1.5
Fix storage.rs serialization — resolve indices before persisting
Serializing a raw u32 index is meaningless. Either walk the live set and serialize actual data, or switch to mmap-backed slab persistence (msync / mmap). The mmap path is architecturally cleaner and makes crash recovery free.

Blocks Phase 2 Phase 3
Phase 2 Cycle collection — Bacon-Rajan trial deletion First real fix for the cycle leak
2.1
Implement trial deletion collector in ifa-memory
Bacon-Rajan operates on the reference count graph. Suspects are flagged, counts are decremented in a local pass, and subgraphs that reach zero are reclaimed. Keeps RC semantics — no full heap tracing. This is the easiest upgrade from the current Arc model.
ifa-memory
2.2
Wire collection trigger into OponSlab
Trigger per-actor collection when allocation crosses a configurable threshold (informed by kernel.rs available memory). No global pause — each actor collects independently. The Opon registry already has the root set.
ifa-vm
2.3
Scope Babalawo correctly — trivial cycles only
Babalawo remains useful for catching a = [a]-style literals at compile time, and for emitting a warning when a value visibly crosses a function boundary into a mutable container. It must not attempt inter-procedural cycle detection — that is the runtime collector's job.
ifa-vm
Blocks Phase 3 (GC backends)
Phase 3 Target-specific GC backends Only after profiling justifies the complexity
3.1
Native: per-actor generational semi-space copying collector
Flip to new slab, trace from actor stack roots, copy live data, discard old slab. Cycles are destroyed — unreachable objects simply aren't copied. Pointer fixup is index remapping. Pauses only one actor at a time.
ifa-memory
3.2
WASM: cooperative copying GC at yield points
Per-coroutine slab regions within WASM linear memory. GC runs at await / yield points — acceptable since there is only one thread. No mprotect; copying must stay within a single Vec<u8> / ArrayBuffer.
ifa-memory
3.3
Embedded Tier 0: epoch reclamation, no GC
Bulk free at ebo scope exit. FixedBackend<256> — compile-time error on overflow. Replace EmbeddedValue with shared IfaValue (u32 index). Merge embedded opcodes with main opcode set.
ifa-embedded
3.4
Unified CPU/GPU slab for native UMA targets
On Apple Silicon / integrated GPU, the CPU RamBackend and GPU GpuBackend can share physical memory. Note: wgpu does not currently expose UMA as a first-class API — treat as a future optimisation, not a near-term target.
ifa-infra
Phase 4 Auto-tuning and observability Quality-of-life — can be done in parallel with Phase 3
4.1
Auto-tune slab size from kernel.rs at startup
Query available_memory() and num_cores() to select OponSize::Kekere / Nla / etc. Feed slab stats counters (already present in the GPU slab) into GC heuristics.
ifa-infra
4.2
Land Ikin read-only global region
Compile-time constants (string literals, bytecode templates) into .rodata on native, WASM data segment on WASM, flash on embedded MCUs. Zero RAM cost on read. Shared across all actors — no slab allocation needed for constants.
