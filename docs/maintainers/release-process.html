release.ifa

    — Release Process

    Tag-based release pipeline — source-verified from .github/workflows/release.yml

    Source-verified. Extracted from .github/workflows/release.yml (153 lines) and root Cargo.toml (workspace config).

    1. Trigger

    Pushing a v* tag to GitHub triggers the release workflow (release.yml:4):

    on:
  push:
    tags:
      - 'v*'

    Pre-release detection (release.yml:139): if the tag contains -alpha, -beta, or -rc, the release is marked as a prerelease on GitHub.

    3. Artifacts Built

    Each build job produces (release.yml:79-91):

    • ifa-<version>-<platform> — the primary CLI binary (cargo build --release -p ifa-cli)
    • ifa-installer-<version>-<platform> — GUI installer binary (cargo build --release -p ifa-installer-gui), skipped for cross-compiled targets

    Artifacts are uploaded with 1-day retention (release.yml:93-97).

    4. Release Assembly

    The release job (release.yml:101) runs after all builds complete:

    1. Downloads all platform artifacts
    2. Generates sha256sum checksums (release.yml:113-117)
    3. Generates release notes from git log since previous tag (release.yml:119-141)
    4. Creates a GitHub Release with all artifacts attached (release.yml:143-150)

    5. Versioning

    Workspace version: 1.3.0 (Cargo.toml:22). Crate versions:

    • Most crates inherit workspace version (1.3.0)
    • ifa-bytecode uses standalone 0.1.0 with edition 2021
    • ifa-installer-core uses standalone 0.1.0
    • ifa-installer-gui uses standalone 0.1.0

    Release tag format: v<workspace_version> (e.g., v1.3.0).

    6. docs.rs

    Only ifa-bytecode has docs.rs metadata configured (Cargo.toml:19-20): all-features = true. No other crate has [package.metadata.docs.rs], documentation, or homepage fields.
