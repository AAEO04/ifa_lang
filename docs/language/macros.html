Procedural Macros

Cultural Safety Features & Reactive Programming

Important: These macros are Rust-side procedural macros defined in the ifa-macros crate. They operate on Rust structs/functions, not on Ifa-Lang source code. Ifa-Lang does not have a user-facing macro system in the grammar/parser. These macros are used when embedding Ifa-Lang in Rust or when extending the runtime via Rust.

Overview

Ifa-Lang's procedural macros provide compile-time safety checks and code generation that embody Yoruba cultural principles. These macros ensure resource safety, balance checking, and reactive relationships in your Rust code that interfaces with the Ifa-Lang runtime.

#[derive(Ebo)] - Resource Sacrifice

Automatically implements Drop trait for RAII resource cleanup. The macro embodies the Yoruba concept of ebo (sacrifice/offering) where resources must be properly returned to the system.

Basic Usage

Ebo Derive 
use ifa_macros::Ebo;

#[derive(Ebo)]
struct MyFile {
    handle: std::fs::File,
}

// Drop is auto-implemented:
// impl Drop for MyFile {
//     fn drop(&mut self) {
//         println!("[Ebo] Sacrificed: MyFile");
//     }
// }

Custom Cleanup Method

Custom Ebo 
use ifa_macros::Ebo;

#[derive(Ebo)]
#[ebo(cleanup = "close")]
struct DatabaseConnection {
    pool: sql::Pool,
}

impl DatabaseConnection {
    fn close(&mut self) {
        self.pool.close();
    }
}

// Generates:
// impl Drop for DatabaseConnection {
//     fn drop(&mut self) {
//         println!("[Ebo] Sacrificing DatabaseConnection");
//         self.close();
//     }
// }

Attribute Parameters

  • cleanup = "method" - Specify custom cleanup method name (optional)
  • Default: Prints sacrifice message without explicit cleanup call

#[iwa_pele] - Gentle Balance

Compile-time balance checking for paired operations. Iwa Pele (gentle character) ensures that resources opened in a scope are properly closed in the same scope, preventing resource leaks.

Checked Operation Pairs

  • so / pa - open/close
  • si / ti - file open/close
  • mu / fi - acquire/release
  • bere / da - start/stop

Usage Example

Balance Checking 
use ifa_macros::iwa_pele;

#[iwa_pele]
fn network_task() {
    let conn = open("example.com", 80);  // open (so)
    // ... work with connection
    close(conn);  // close (pa) - REQUIRED or compile error
}

// This would cause compile error:
// #[iwa_pele]
// fn bad_function() {
//     let file = open_file("data.txt");  // open file (si)
//     // Missing: close_file() - compile error!
//     // Iwa Pele violation: Block leaks resource
// }

Compile-Time Enforcement

The macro performs lexical CFG (Control Flow Graph) analysis at compile time:

  • Zero Runtime Cost: No runtime overhead
  • Lexical Scope: Checks within each block
  • Clear Errors: Detailed violation messages
  • Early Detection: Catches leaks before execution

ajose! - Reactive Binding

Creates reactive bindings between values. Ajose (gathering/assembly) represents the reactive system where changes propagate through relationships automatically.

Basic Reactive Binding

Standard Binding 
use ifa_macros::ajose;
use std::cell::RefCell;

let counter = RefCell::new(0);
let label = RefCell::new("0".to_string());

// Create reactive binding
ajose!(counter => label);

// When counter changes, sync to label
*counter.borrow_mut() = 42;

Freeze Binding (Cross-thread)

Thread-Safe Binding 
use ifa_macros::ajose;
use std::sync::{Arc, Mutex};
use std::cell::RefCell;

let shared_data = Arc::new(Mutex::new(Vec::new()));
let local_counter = RefCell::new(0);

// Auto-freeze for cross-thread safety
ajose!(local_counter => #freeze shared_data);

// Creates frozen value safe for sharing across threads

Generated Code

The macro generates subscription logic and initial synchronization:

  • Subscription Creation: Closure for value changes
  • Initial Sync: Sets target to source value
  • Freeze Logic: Optional thread-safe freezing via #freeze modifier
  • Debug Output: Binding creation logging

ebo_block! - Scoped Resource Management

Creates a scoped RAII block with guaranteed cleanup. The block embodies the concept of ritual boundaries where resources are managed within a sacred space.

Usage

Ebo Block 
use ifa_macros::ebo_block;

ebo_block! {
    let file = std::fs::File::open("data.txt")?;
    let conn = Database::connect("localhost")?;
    
    // Work with resources
    process_data(&file, &conn)?;
    
    // All resources auto-cleanup when block exits
}

// Output:
// --- Ebo Block Started ---
// [Work happens here]
// --- Ebo Block Complete ---

Generated Structure

The macro creates a guard struct with Drop implementation:

  • Guard Creation: _EboGuard instance
  • Start Logging: Block initiation message
  • Drop Implementation: Completion logging
  • Scope Safety: Guaranteed cleanup

#[derive(Observable)] - Reactive Data

Makes a struct's fields observable for reactive updates. Generates watcher methods for each field, enabling reactive programming patterns.

Basic Usage

Observable Struct 
use ifa_macros::Observable;

#[derive(Observable)]
struct Counter {
    value: i32,
    name: String,
}

// Generated methods:
// impl Counter {
//     pub fn watch_value(&self, callback: F) { ... }
//     pub fn watch_name(&self, callback: F) { ... }
// }

Reactive Pattern

Reactive Usage 
let counter = Counter { value: 0, name: "counter".to_string() };

// Watch for changes
counter.watch_value(|val| {
    println!("Value changed to: {}", val);
});

Generated Features

  • Field Watchers: watch_{field_name} methods
  • Type Safety: Generics for callback types
  • Logging: Debug output for watcher creation
  • Struct Only: Works only on struct types

Integration with Runtime Specification

Cultural Safety

These macros embody Yoruba cultural principles:

  • Ebo (Sacrifice): Resources must be properly returned
  • Iwa Pele (Gentle Character): Balance and harmony in operations
  • Ajose (Gathering): Community of reactive relationships
  • Sacred Boundaries: Scoped resource management

Note on Ifa-Lang Macro System

These macros exist at the Rust level for developers embedding Ifa-Lang or building runtime components. Ifa-Lang itself does not have a user-facing macro/metaprogramming system in its grammar. A future version may introduce language-level macro support for code generation at the Ifa-Lang source level.

Example: Complete Rust Integration

Integrated Macro Usage 
use ifa_macros::{Ebo, Observable, iwa_pele, ebo_block};

// Observable data structure
#[derive(Observable)]
struct AppState {
    counter: i32,
    status: String,
}

// Resource with automatic cleanup
#[derive(Ebo)]
#[ebo(cleanup = "disconnect")]
struct DatabaseConnection {
    pool: sql::Pool,
}

impl DatabaseConnection {
    fn disconnect(&mut self) {
        self.pool.close();
    }
}

#[iwa_pele]
fn main() {
    ebo_block! {
        let conn = DatabaseConnection { pool: sql::Pool::new() };
        let state = AppState { counter: 0, status: "ready".into() };
        
        // Watch for changes
        state.watch_status(|status| {
            println!("Status: {}", status);
        });
        
        state.counter = 42;
        state.status = "processing".into();
        
        // conn automatically disconnected on block exit
    }
}
