    Native Array Methods

    Ergonomic method-call syntax for arrays, coexisting with Ogunda and Cpu

    Ifá-Lang now supports native methods directly on array values — my_array.map(closure), my_array.sort(), and more. These coexist with the existing Ogunda domain procedures and the Cpu infrastructure domain, each serving a different paradigm.

    Available Methods

    These methods are implemented directly in the VM (vm.rs) and work on any List / Array value:

    ayanmo numbers = [3, 1, 4, 1, 5, 9];

// Map — apply a closure to each element
ayanmo doubled = numbers.map(fn(x) { x * 2 });
// [6, 2, 8, 2, 10, 18]

// Sort — in-place mutation
numbers.sort();
// [1, 1, 3, 4, 5, 9]

// Filter — keep elements matching a predicate
ayanmo evens = numbers.filter(fn(x) { x % 2 == 0 });
// [4]

// Reduce — fold over elements
ayanmo sum = numbers.reduce(fn(acc, x) { acc + x }, 0);
// 23

// Find — first match
ayanmo first = numbers.find(fn(x) { x > 5 });
// 9

// Every / Some — boolean checks
ayanmo all_positive = numbers.every(fn(x) { x > 0 });
ayanmo has_zero = numbers.some(fn(x) { x == 0 });

    Relationship with Ogunda

    The Ogunda domain (docs/domains/ogunda.html) is unaffected by native methods, but for many cases the new syntax is more ergonomic:

    ApproachSyntaxMechanism
    Native method my_array.map(fn(x) { x * 2 }) Direct VM dispatch via vm.rs — executes bytecode closures in an isolated context
    Ogunda Ogunda.map(my_array, my_closure) Uses ctx.call_value → spawn_task / await_future in vm_registry.rs

    Both use the same isolated execution mechanism under the hood. There is no performance penalty for choosing one over the other. Ogunda continues to work perfectly as a pure functional library — choose whichever style fits your code.

    Relationship with Cpu

    The Cpu domain (docs/infrastructure/infra/cpu.html) is also unaffected. It operates on a completely different tier of data:

    AspectNative .map()Cpu.par_map()
    DataAny IfaValue — strings, nested maps, objects, mixed typesExclusively CpuOponView — a zero-copy f32 hardware buffer wrapped in a Resource token
    ClosuresArbitrary Ifá-Lang bytecode closuresString identifiers for pre-compiled Rust math kernels ("square", "double", "abs")
    ExecutionVM interpreter loop (per-element)Rayon parallel iterator over native CPU vectors
    SortingGeneric dynamic sort via IfaValue::partial_cmp — handles mixed types safelyStrips VM boxing, converts to raw f64/i64 vectors, sorts with native CPU SIMD

    When to Use Which

    • Day-to-day scripting: Use my_array.map() — modern, ergonomic, works with any data type.
    • Functional pipelines: Use Ogunda.map() when you prefer a procedural style or are already in an Ogunda-heavy codebase.
    • High-performance numerical computation: Use Cpu.par_map() and Cpu.par_sort() — they bypass the VM interpreter loop entirely and operate on native hardware buffers in parallel.
