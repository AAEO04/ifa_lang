Philosophy of Ifa-Lang

The 16 Odu Domains - Sacred Patterns of Programming

Core Philosophy

Ifa-Lang is built on Yoruba cosmology where every aspect of programming maps to an Odu - the sacred patterns of Ifa divination. The language embodies the principle that programming is a form of divination, where we seek wisdom through structured patterns and logical reasoning.

"A ki i wo oun kan soso." - One never looks in only one direction.
Every problem has multiple perspectives; the 16 Odu provide different approaches to programming challenges.

The Three-Tier Runtime Model

Ifa-Lang implements a unified three-tier execution model that mirrors the three levels of Yoruba spiritual hierarchy:

1. AST Interpreter (The Diviner)

  • Role: Direct interpretation of source code
  • Speed: Development and debugging
  • Use Case: REPL, rapid prototyping
  • Character: Immediate wisdom, clear understanding

2. Bytecode VM (The Oracle)

  • Role: Optimized bytecode execution
  • Speed: Production performance
  • Use Case: Compiled applications
  • Character: Efficient execution, reliable results

3. Transpiler (The Messenger)

  • Role: Translation to native targets
  • Speed: Maximum performance
  • Use Case: Embedded systems, WASM
  • Character: Universal communication, platform bridging

Protocol-Oriented Design

Ifa-Lang rejects traditional object-oriented programming in favor of a protocol-oriented data model. This aligns with Yoruba philosophy where relationships and capabilities matter more than rigid hierarchies.

No Classes or Inheritance

Note: The grammar does include an odu (class) definition construct (odu Server { }), but the language does not implement classical inheritance. The odu keyword defines domain-like structs with methods, closer to a module or protocol than a traditional class.

  • Instead of classes: Values implement protocols (capabilities)
  • Instead of inheritance: Structural subtyping via Babalawo analysis
  • Instead of interfaces: Odu domain contracts

Values Have Character (Iwa)

"Iwa l'ewa." - Character is beauty.
In Ifa-Lang, types encode character, not just structure. A FileHandle isn't just a descriptor - it's a value with obligations.

The 16 Odu Domains

Each Odu represents a fundamental aspect of programming, with a binary pattern that reflects its character:

1111 Ogbe

System - Version info, CLI args, lifecycle

The fully illuminated - complete system access

0000 Oyeku

Exit/Sleep - Process termination, sleep, halt

The void - termination and pause

0110 Iwori

Time - Current time, timestamps

The beginning - temporal awareness

1001 Odi

File I/O - Read, write, file existence

The obstacle - persistent storage

1100 Irosu

Console - Print, read input, clear, error output

The speaker - communication and interface

0011 Owonrin

Random - Random number generation

The wanderer - entropy and chance

1000 Obara

Math - Add, multiply, power, sqrt

The calculation - mathematical operations

0001 Okanran

Assertions - Assert, throw/panic

The troublemaker - validation and errors

1110 Ogunda

Collections - List ops: len, push, pop, map, filter, reduce

The transformation - data processing

0111 Osa

Concurrency - Sleep, all/join, spawn (via ifa-vm)

The abundance - parallel execution

0100 Ika

Strings - Length, slice, concat, HTML title/strip

The measurement - text processing

0010 Oturupon

Math (inverse) - Subtract, divide

The opposition - inverse operations

1011 Otura

Networking - HTTP GET/POST, listen, connect (requires backend feature)

The transmission - communication

1101 Irete

Crypto - SHA-256, HMAC, base64, compress (requires crypto feature)

The crusher - data transformation and security

1010 Ose

Graphics/TUI - Drawing, read key, box/section (requires game feature)

The creation - visual representation

0101 Ofun

Meta - eval (le), debug

The completion - introspection and capabilities

Infrastructure Domains

Beyond the 16 principal Odu, the runtime exposes infrastructure domains for hardware/OS access:

  • Cpu (ID 18) - Parallel computing via rayon: map, reduce, sort, buffer ops
  • Gpu (ID 19) - GPU compute via wgpu: pipeline dispatch, buffer ops (requires gpu feature)
  • Storage (ID 20) - Key-value persistence (requires persistence feature)
  • Sys (ID 29) - Kernel/OS interface: num_cores, total_memory, available_memory, uptime

The 256 Odu Lattice Vision

In the long-term design, the 256 Odu combinations become the 256 fundamental type categories. Each combination represents a specific character of program behavior:

Type Characters

  • Ogbe + Oyeku (1111 + 0000): The full-to-empty transformation - compression, hashing, encryption
  • Odi + Otura (1001 + 1011): Storage + transmission - serializable types
"The 256 Odu as a type lattice is the horizon this language is moving toward. It is not the current state. It is the direction."
This vision guides the evolution of Ifa-Lang's type system.

Memory Management: Opon

Opon (the divination tray) is Ifa-Lang's memory management system, inspired by the physical divination tray used in Ifa ceremonies.

Memory Philosophy

  • Sacred Space: Memory is a sacred space for computation
  • Ritual Cleanup: Resources must be properly closed
  • Pattern Recognition: Memory allocation follows sacred patterns

Opon Directives

The language supports memory size directives that configure the VM stack:

  • #opon kekere - Small memory (256 value slots, 64 call frames)
  • #opon arinrin - Medium memory (4096 value slots, 512 call frames, default)
  • #opon nla - Large memory (65536 value slots, 4096 call frames)
  • #opon ailopin - Unlimited memory

Resource Lifecycle: Ebo

The ebo keyword creates a scoped memory epoch - allocations within the block are released when the scope exits. The defer keyword schedules cleanup at scope exit.

Reactive System: Ajose

Ajose (the gathering) is Ifa-Lang's reactive system for managing dependencies and updates. It embodies the Yoruba concept of community gathering where changes propagate through relationships.

Current status: The ajose! reactive binding macro exists in the ifa-macros proc-macro crate for Rust-level use. Language-level reactive syntax is not yet implemented in the Ifa-Lang parser/grammar.

Reactive Philosophy

  • Community: Values exist in relationship to each other
  • Communication: Changes are communicated through the system
  • Adaptation: The system adapts to changing conditions

Bilingual Design

Ifa-Lang is fundamentally bilingual, supporting both Yoruba and English keywords. This reflects the dual nature of wisdom - traditional and modern, sacred and practical.

Language Philosophy

  • Accessibility: Both native speakers and learners can use the language
  • Cultural Preservation: Yoruba terminology preserves cultural knowledge
  • Universal Understanding: English terms provide global accessibility
  • Cognitive Diversity: Multiple perspectives enhance problem-solving
Bilingual Examples 
// Variable declaration
ayanmo name = "Ifa";          // Yoruba
let name = "Ifa";             // English

// Function definition  
ese greet(name) { ... }       // Yoruba
fn greet(name) { ... }        // English

// Error handling
gbiyanju { ... } gba(e) { ... }    // Yoruba  
try { ... } catch(e) { ... }       // English

// Assertions
ewo x > 0;                    // Yoruba (ewo/verify)
assert x > 0;                 // English (assert/verify)

Taboo System: Eewo

Eewo (taboo) defines architectural constraints and safety rules. In Yoruba tradition, taboos protect the community from harm; in Ifa-Lang, they protect the program from errors and vulnerabilities.

Current status: The grammar includes a taboo_stmt rule for declaring domain-to-domain taboos (eewo: Ose -> Odi;). The Babalawo static analyzer performs basic taboo validation. Full compile-time enforcement is under development.

Architectural Taboos

  • Thread Safety: Certain operations are taboo in multi-threaded contexts
  • Resource Management: Leaking resources is taboo
  • Type Safety: Violating type contracts is taboo
Taboo Declaration 
// Declare taboo: Ose (Graphics) -> Odi (Errors)
eewo: Ose -> Odi;

Grammar Notes

Implemented Grammar Rules

The Ifa-Lang grammar (defined in grammar.pest) includes these major rules: program, statement (with ~25 variants), expression (with full binary/unary operators, precedence), odu_call, if_stmt, while_stmt, for_stmt, match_stmt, try_stmt, ese_def, odu_def, import_stmt, const_stmt, taboo_stmt, ewo_stmt, yield_stmt, defer_stmt, ailewu_stmt, and others.

Planned Grammar Rules

  • eku: The eku grammar rule (for method dispatch / domain routing in the Opele compound Odu system) is not yet implemented. It is reserved for a future extension where the 240 derived Odu combinations receive explicit grammar support.

Conclusion: Wisdom Through Patterns

Ifa-Lang represents a synthesis of ancient wisdom and modern programming. The 16 Odu domains provide a comprehensive framework for thinking about programming problems, while the protocol-oriented design ensures flexibility and safety.

"Programming is divination. Code is prayer. Execution is revelation."
Through the sacred patterns of the Odu, we seek not just to instruct machines, but to gain wisdom in the process of creation.

The language continues to evolve toward the vision of the 256 Odu lattice, where types encode not just structure but character, and where every program becomes a form of sacred communication between human intent and machine execution.
