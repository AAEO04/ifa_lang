Type System

ifa-types - Shared Foundation for All Runtimes

Overview

The ifa-types crate provides the canonical shared type system used across all Ifa-Lang runtime components. It ensures type consistency between the interpreter, bytecode VM, transpiler, and standard library. The crate is no_std compatible (requires alloc feature for heap types).

"This is the ONE error type. ifa-vm, ifa-std, ifa-cli all re-export it. If you need a different error shape, use a different type name - never another IfaError."
Single source of truth principle enforced across all crates

Key crate attributes: #![forbid(unsafe_code)], #![no_std] (with std feature for full std support). NaN boxing is used for primitive value optimization on 64-bit platforms.

Feature Flags

  • vm: Include AST, bytecode, binary_ops modules
  • std: Enable standard library extensions (capability, registry, etc.)
  • alloc: Enable heap allocation support for no_std
  • serde: Enable serialization support
  • dashmap: Use DashMap for concurrent IfaShared objects
  • default: Core types only (no_std compatible)

IfaValue - Dynamic Type System

The universal container for Ifa-Lang's dynamic typing. Implemented as a regular Rust enum (not a hand-packed union) with 16-byte size on 64-bit systems.

Current Implementation (value_union.rs)

IfaValue Variants 
// IfaValue is a regular Rust enum (16 bytes on 64-bit)
pub enum IfaValue {
    // Primitives (Inline, No Alloc)
    Null,
    Bool(bool),
    Int(i64),
    Float(f64),

    // Heap Objects (Ref-Counted via Arc)
    Str(Box<String>),                   // Heap-allocated string
    List(Arc<Vec<IfaValue>>),       // Immutable list
    Map(Arc<HashMap<CompactString, IfaValue>>),  // Immutable map

    // Function types
    Fn(Arc<BytecodeFnData>),        // Bytecode function

    // Resource handle
    Resource(Arc<ResourceToken>),   // Opaque resource token

    // Result type (Okanran)
    Result(Box<ResultPayload>),     // Ok(value) | Err(value)

    // VM-only variants (feature = "vm")
    #[cfg(feature = "vm")]
    AstFn(Arc<AstFnData>),          // AST function (interpreter)
    #[cfg(feature = "vm")]
    Upvalue(UpvalueCell),            // Closure upvalue
    #[cfg(feature = "vm")]
    Closure(Arc<ClosureData>),       // Bytecode closure
    #[cfg(feature = "vm")]
    Future(FutureCell),              // Async future
    #[cfg(feature = "vm")]
    Actor(Arc<ActorData>),
    #[cfg(feature = "vm")]
    Return(Arc<IfaValue>),           // Return signal
    #[cfg(feature = "vm")]
    Break,                           // Loop break signal
    #[cfg(feature = "vm")]
    Continue,                        // Loop continue signal
}

Performance Optimizations

  • Box<String>: 8-byte thin pointer keeps IfaValue at 16 bytes
  • Arc/IfaGc: Reference-counted sharing for heap types
  • Small Int Pool: Integers 0-255 are cached (with std feature)

Legacy Implementation (value.rs — deleted)

The legacy value.rs module has been deleted. Only value_union.rs remains as the canonical IfaValue definition. All imports across the workspace use ifa_types::IfaValue directly.

IfaError - Canonical Error System

The single authoritative error type used across all Ifa-Lang components. Embodies the Okanran (Errors) domain with Yoruba proverbs.

Error Categories

Math Errors (Obara / Oturupon) - ErrorCode 0x03XX

  • DivisionByZero: "Division by zero - Obara rejects: {context}"
  • Overflow / Underflow: Numeric overflow/underflow

Type Errors - ErrorCode 0x02XX

  • ArityMismatch: Wrong number of arguments
  • ArgumentError: Invalid argument values
  • TypeError: Expected vs actual type conflict
  • ConversionError: Type conversion failures

Index/Key Errors (Ogunda / Ika) - ErrorCode 0x01XX

  • IndexOutOfBounds: Array/collection index errors
  • KeyNotFound: Map key missing errors

I/O Errors (Odi / Irosu) - ErrorCode 0x04XX

  • FileNotFound / PermissionDenied / IoError
  • ConnectionFailed / Timeout / SsrfBlocked

VM Errors - ErrorCode 0x00XX

  • UnknownOpcode / StackUnderflow / StackOverflow
  • UndefinedVariable / UndefinedFunction
  • OponExhausted - Memory pool exhausted
  • AsyncNotAvailable
  • Exit(i32) - Process exit signal

Error Integration

Error Usage (Rust-side) 
// Result type alias
pub type IfaResult<T> = Result<T, IfaError>;

// Usage across all crates
use ifa_types::{IfaError, IfaResult};

fn divide(a: i64, b: i64) -> IfaResult<i64> {
    if b == 0 {
        Err(IfaError::DivisionByZero("Cannot divide by zero".into()))
    } else {
        Ok(a / b)
    }
}

IfaShared - The Village Data Store

The thread-safe value type for inter-thread communication and global state. Uses Arc<RwLock> or DashMap for concurrent access.

IfaShared Variants 
pub enum IfaShared {
    Int(i64),
    Float(f64),
    Str(Arc<str>),
    Bool(bool),
    List(Vec<IfaShared>),         // Value-type list
    Map(HashMap<Arc<str>, IfaShared>),  // Value-type map
    Object(Arc<DashMap<Arc<str>, IfaShared>>),  // Concurrent map
    Fn(IfaSharedFn),               // Thread-safe function
    Resource(ResourceToken),
    Null,
}
  • Freeze: Convert IfaValue to IfaShared for thread-safe sharing
  • Thaw: Convert IfaShared back to local IfaValue
  • Send + Sync: All variants are thread-safe

Resource Management

ResourceRegistry (Olubode - The Gatekeeper)

Global registry storing system resources (files, sockets, DB connections) across threads. Users hold ResourceToken IDs while the actual resource lives in the registry.

  • Safe: Resources are stored as Arc<dyn Any + Send + Sync> for type-safe downcasting
  • Owned: Each resource is associated with an owner actor ID
  • Lifecycle: Registry is managed by the runtime, cleared on VM shutdown

Traits and Protocols

Core Traits (traits.rs)

  • CpuOps: Parallel computing operations (par_sum, par_map, configure)
  • GpuOps: GPU compute operations
  • StorageOps: Key-value storage
  • BackendOps: HTTP server/request operations
  • FrontendOps: HTML/CSS generation
  • CryptoOps: SHA-256, SHA-512, Argon2
  • MlOps: Tensor operations, matrix multiplication
  • GameDevOps: 2D/3D vector operations
  • IotOps: GPIO pin operations

Protocol-Oriented Design

Traits define interfaces for Odu domain operations. These traits are implemented by ifa-std and called from ifa-vm.

VM Features (Optional)

When the vm feature is enabled, additional modules are available:

AST Module

  • Statement Enum: ~25 statement types including VarDecl, If, While, For, Match, Try, etc.
  • Expression Types: Binary/unary ops, lambda, method calls, property access
  • Type Hints: High-level (Int, Float, Str, Bool) and low-level (i8-u64, F32-F64, pointers)

Bytecode Module

  • Bytecode Struct: Instruction representation with constant pool
  • OponSize: Memory pool sizing (Kekere, Arinrin, Nla, Ailopin)
  • OpCode Integration: ifa-bytecode crate integration

Binary Ops Module

Type compatibility checking for binary operators: checks numeric types, string concatenation, etc.

}

Serialization Support

serde Integration

Most types support serde serialization/deserialization when serde feature is enabled:

  • OduDomain: Full enum serialization
  • IfaValue: Surrogate-based serialization (Null, Bool, Int, Float, Str, List only)
  • IfaError: Serialization support

Serialization Limitations

  • Functions: Cannot serialize Fn, Closure, AstFn variants
  • Upvalues: Not serializable
  • Futures: Not serializable
  • Actors: Not serializable
  • Resources: Not serializable
  • Return/Break/Continue: Internal signals, not serializable

Usage Guidelines

Import Patterns (Rust)

Recommended Imports for Rust Crates 
// Standard imports for most crates
use ifa_types::{
    IfaValue, IfaError, IfaResult,
    OduDomain, IfaShared, ResourceToken,
    CompactString,
};

// VM-specific imports
#[cfg(feature = "vm")]
use ifa_types::{Statement, Bytecode};

Best Practices

  • Single Source: Always import from ifa-types, never redefine
  • Error Handling: Use IfaResult for all fallible operations
  • Domain Types: Use OduDomain for domain-specific operations
  • Resource Safety: Use ResourceToken for managed resources
  • Thread Safety: Use IfaShared::freeze() for cross-thread value sharing

Performance Considerations

  • CompactString: Prefer for string values - provides small string optimization
  • NaN Boxing: Primitive VM operations use NaN-boxed fast path
  • Arc Sharing: Lists and maps use Arc for zero-copy sharing
  • Feature Flags: Disable VM features when not needed to reduce binary size
