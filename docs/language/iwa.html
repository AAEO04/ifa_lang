    Iwa — Protocol-Oriented Structural Typing

    Structural protocols with lifecycle tracking (Ìwà = character/conduct)

    1. What is Iwa?

    Iwa (Yoruba: "character" / "conduct") is Ifá-Lang's protocol-oriented type system. Like Rust's traits, Go's interfaces, or TypeScript's structural types — but with lifecycle-aware method pairing.

    An iwa defines a set of method signatures that a value must implement. Any value that satisfies the shape (structural typing) automatically conforms — no explicit impl declaration needed.

    2. Basic Protocol

    iwa Logger {
    log(msg: Str) -> Ase;
}

ayanmo logger: Iwa<Logger> = Obara.fikun(42);
// Error: Int does not satisfy Iwa 'Logger': missing method 'log'

// A Map with the right shape satisfies Iwa Logger:
ayanmo logger: Iwa<Logger> = {
    "log": ese (msg) { Irosu.fo(msg) }
};

    The Babalawo (static analyzer) checks conformance at compile/check time:

    $ ifa check source.ifa
# Error: Variable 'logger' must have Iwa 'Logger' type to be assigned
# Error: Map does not satisfy Iwa 'Logger': missing method 'log'

    3. Iwa Pele — Lifecycle Tracking

    Iwa Pele (Ìwà Pẹ̀lẹ̀ = gentle character) extends protocols with resource lifecycle annotations. Pairs of methods are marked as open/close, and the Babalawo verifies they are balanced.

    iwa File {
    #[iwa_pele_pair(open, close)]
    open(path: Str) -> Result;
    close() -> Result;

    read() -> Str;
}

ayanmo file = Odi.si("data.txt");
file.read();
// file.close() forgotten!
// → Babalawo: Resource 'odi.si' opened at line 3 was never closed (needs 'odi.pa')
    Runtime GC integration: Objects with a known iwa_pele_pair closer that was called are skipped by the cycle collector — their memory is guaranteed to be freed deterministically.

    The built-in lifecycle rules (crates/ifa-babalawo/src/iwa.rs:11-44):

    DomainOpenerCloserDescription
    Odi (File)odi.siodi.paOpen → Close
    Otura (Net)otura.deotura.paBind → Close
    Otura (Net)otura.sootura.paConnect → Close
    Ogunda (Alloc)ogunda.geirete.tuAlloc → Free
    Ofun (Object)ofun.daofun.paCreate → Delete
    Ogbe (System)ogbe.bioyeku.duroInit → Halt

    4. Iwa Type Hints

    Function parameters and return types can declare Iwa constraints:

    // Parameter must satisfy Iwa Logger
ese process(handler: Iwa<Logger>) {
    handler.log("Starting...");
}

ese make_logger() -> Iwa<Logger> {
    pada {
        "log": ese (msg) { Irosu.fo(msg) }
    }
}

ayanmo logger = make_logger();   // type: Iwa<Logger>
process(logger);                  // OK: satisfies constraint
