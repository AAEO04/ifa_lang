    1. Main Execution Loop

    IfaVM::execute() (vm.rs:525) is the entry point. It:

    1. Resets IP and halted flag
    2. Loads the Ikin constant pool from bytecode (vm.rs:533)
    3. Sets stack/frame capacity limits from OponSize
    4. Calls resume_execution()

    resume_execution() (vm.rs:868) is the main loop:

    while !self.ctx.halted && ip < bytecode.code.len() {
    self.ctx.ip = ip;
    if let Err(e) = self.step(bytecode) {
        if matches!(e, IfaError::Yielded) {
            return Err(e);  // suspend for async
        }
        if self.attempt_recovery(&e)? {  // Shield of Ọkànràn
            ip = self.ctx.ip;
            continue;
        }
        return Err(e);
    }
    ip = self.ctx.ip;
}

    2. Opcode Dispatch (Irokè)

    step() (vm.rs:1152) uses a single match opcode { ... } — not a handler chain. Each opcode variant is dispatched directly in one level of pattern matching.

    tap() (vm_iroke.rs:17) handles fetch + decode:

    #[inline(always)]
pub fn tap(vm: &mut IfaVM, bytecode: &Bytecode) -> IfaResult<OpCode> {
    // Fuel check — every 1024 ticks (bitmask: ticks & 1023 == 0)
    if vm.ticks & 1023 == 0 {
        if let Some(ref mut remaining) = vm.fuel {
            if *remaining == 0 {
                return Err("fuel exhausted");
            }
            *remaining = remaining.saturating_sub(1024);
        }
    }
    vm.ticks = vm.ticks.wrapping_add(1);

    // Bounds check, fetch byte, decode via OpCode::from_u8()
    let byte = bytecode.code[vm.ctx.ip];
    vm.ctx.ip += 1;
    OpCode::from_u8(byte).ok_or_else(|| ...)
}

    Key dispatch properties:

    • Fuel decremented in chunks of 1024 — amortized, not per-opcode
    • Bounds-check on instruction fetch (safe for interpreter, would omit in JIT)
    • 93 opcode variants defined in ifa-bytecode/src/lib.rs:42
    • Each variant has: mnemonic, operand_bytes, stack_effect (defined inline)

    4. Stack & Call Frames

    The stack is a flat Vec<IfaValue> in ExecutionContext (vm.rs:199). Locals are addressed by base_ptr + offset from the current CallFrame.

    CallFrame fields (vm.rs:28):

    FieldTypePurpose
    return_addrusizeIP to resume after call returns
    base_ptrusizeStack index where this frame's locals begin
    local_countusizeNumber of local variables in this frame
    closure_envOption<Arc<Vec<UpvalueCell>>>Captured upvalues if this is a closure call
    async_returnboolTrue if the return value should be wrapped in a Future

    Limits:
      Default: stack = 4096, frames = 512 (vm.rs:338-339)
      Sandbox: stack = 1024, frames = 128 (vm.rs:372-373)

    5. Function Calls

    Regular calls (dispatch_call() at vm.rs:1429): pushes a new CallFrame, copies arguments onto stack, sets IP to callee.

    Tail calls (dispatch_tail_call() at vm.rs:2363): reuses the current call frame instead of pushing a new one:

    1. Pop function + arguments from stack
    2. Truncate stack to frame.base_ptr
    3. Update existing frame's closure_env and local_count
    4. Push arguments onto truncated stack
    5. Set IP to callee's start_ip — frame count unchanged

    Compiler emits TailCall for return f(x) patterns (ifa-compiler/src/lib.rs:592).

    Async tail calls: spawn a task and pop the current frame (vm.rs:2397-2409), wrapping the result in a Future.

    6. Async Task System

    Cooperative, single-threaded. No preemption.

    FunctionLineRole
    spawn_task()vm.rs:1064Creates Task with fresh ExecutionContext, pushes to task_queue (VecDeque). Returns a Future value.
    run_task_slice()vm.rs:948Swaps ExecutionContext with task, runs step() in a loop until frames unwind to base_depth (completion) or Yield (suspend).
    poll_one_task()vm.rs:982Pops front of queue, runs one slice. If completed, sets FutureState::Ready. If suspended, pushes back to queue.
    await_future()vm.rs:1000Busy-polls future: checks state, calls poll_one_task() if pending.

    OpCode::Yield returns Err(IfaError::Yielded), which propagates up to run_task_slice() and causes the task to be re-queued.

    7. Actors

    True OS-thread parallelism (not cooperative).

    • actor.rs — spawns isolated VMs on separate OS threads
    • Communication via bounded channels: SyncSender<ActorMsg> (capacity 64)
    • ActorTable is Arc-shared across parent VM + all actor threads
    • Created through VmContext::spawn_actor() (native.rs:27)
    • Messaging via VmContext::actor_send() (native.rs:33) — non-blocking, errors on full inbox

    8. Odu Domain Dispatch

    The OduRegistry trait (native.rs:39) bridges VM opcodes to standard library domain implementations:

    • call(domain_id, method_name, args, ctx) — string-based dispatch, called by CallOdu
    • call_fast(domain_id, method_id, args, ctx) (native.rs:63) — integer-based dispatch, called by CallOduFast. Encodes domain + method index in a u16: high byte = domain_id, low byte = method index. Zero string overhead — no method name lookup.
    • import(path) (native.rs:88) — module loading for OpCode::Import

    The concrete registry is provided by ifa-std's vm_registry module, which wires each of the 16 Odù domains into the VM via integer dispatch IDs.

    9. Fuel & Sandboxing

    Fuel (vm.rs:161): fuel: Option<u64>. Checked every 1024 instructions in tap(). Consumed in chunks of 1024. Sandbox mode (vm.rs:370-376) sets fuel = 4096 (4 chunks before exhaustion).

    Capability enforcement: not per-instruction in the VM. The CapabilitySet from ifa-sandbox is checked at the domain handler level (per-call), not in the opcode dispatch loop.

    10. Ikin Constant Pool

    vm_ikin.rs — the runtime constant pool.

    • Ikin stores strings as Arc<str> in a flat Vec
    • O(1) access by index: consult_string(idx) -> Option<Arc<str>>
    • String length cached via Arc pointer for O(1) .len()
    • Loaded from bytecode at execute() time (vm.rs:533)

    11. Error Recovery (Shield of Ọkànràn)

    attempt_recovery() (vm.rs:1082) handles runtime errors:

    1. Pops a RecoveryFrame from ctx.recovery_stack
    2. Restores stack and frame depth to saved snapshots
    3. Pushes the error value as the catch binding
    4. Sets IP to the catch handler
    5. If a finally block exists, stores a FinallyResumption for post-catch execution
