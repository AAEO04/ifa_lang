    §5

    Feature Flag Propagation

    How features cascade from ifa-cli down the dependency tree. Enabling a feature at the top level may pull in optional crates and their dependencies.

    ifa-cli (default = full)
    ├── full → ifa-std/full
    │ ├── ifa-std/full → network + database + tui + async_runtime + crypto + parallel + gpu + persistence + kernel + sysinfo + audio + html
    │ │ ├── network → ifa-sandbox, tokio, reqwest
    │ │ ├── async_runtime → tokio
    │ │ ├── crypto → ring, argon2
    │ │ ├── tui → crossterm, ratatui
    │ │ ├── parallel → ifa-vm/parallel, ifa-infra/parallel
    │ │ ├── gpu → ifa-infra/gpu, wgpu, bytemuck
    │ │ ├── persistence → ifa-infra/persistence, tokio/fs
    │ │ └── database → ifa-sandbox, rusqlite
    ├── full → ifa-vm/std + ifa-vm/sysinfo + ifa-vm/parallel + ifa-vm/gpu + ifa-vm/compiler
    │ ├── ifa-vm/compiler → ifa-parser, ifa-compiler, ifa-transpiler
    │ ├── ifa-vm/native → ifa-sandbox
    │ ├── ifa-vm/parallel → rayon
    │ └── ifa-vm/gpu → wgpu
    └── full → ifa-infra/persistence
    │
    minimal → ifa-vm/std + ifa-vm/compiler + ifa-types/vm

    Key takeaway: The ifa-cli/full feature is the standard path — it enables everything. Use ifa-cli/minimal for CI or restricted builds. The ifa-vm/compiler feature is the gateway that brings in the parser, compiler, and transpiler.
