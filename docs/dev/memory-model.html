memory.ifa

    — Memory Model

    IfaGc cycle collector, Orí heap isolation, and the SendableValue boundary

    Source-verified. Extracted from crates/ifa-types/src/gc.rs, crates/ifa-vm/src/actor.rs, crates/ifa-vm/src/vm.rs, crates/ifa-types/src/value_union.rs.

    1. Architecture Overview

    Ifá-Lang uses a two-track memory management architecture:

    TrackTargetStrategyCrate
    Track A Native (desktop/server) IfaGc<T> — per-actor Bacon-Rajan cycle collector ifa-types::gc
    Track B Embedded (no_std, no alloc) heapless::Slab — bitmap + size classes, no GC ifa-embedded (independent)

    Track A and Track B share no code at the value-representation level. Track B uses EmbeddedValue (8–12 bytes), never IfaValue.

    2. IfaGc — The Cycle Collector

    gc.rs:57-63. IfaGc<T> replaces Arc<T> for heap-backed IfaValue variants that can form reference cycles.

    VariantBeforeAfterWhy
    ListArc<Vec<IfaValue>>IfaGc<Vec<IfaValue>>Lists can contain cycles via mutable references
    MapArc<HashMap>IfaGc<HashMap>Maps can contain cycles (self-referential or recursive)
    SetArc<HashSet>Arc<HashSet> (unchanged)Set semantics make cycles impossible (no ordering)
    ClosureArc<ClosureData>IfaGc<ClosureData>Closures capture environments that can form cycles
    UpvalueArc<Mutex>IfaGc<Mutex>Upvalue cells capture mutable bindings

    CompactString, Arc<BytecodeFnData>, FutureCell (async), and all scalar variants are untouched — they cannot form cycles.

    2.1 Layout

    Each IfaGc allocation carries a CycleHeader (gc.rs:27-38) before the payload data:

    #[repr(C)]
pub struct CycleHeader {
    pub strong: Cell<usize>,         // Reference count
    pub tracing_rc: Cell<usize>,      // Bacon-Rajan tracing count
    pub color: Cell<Color>,            // Black/White/Gray/Purple/Red
    pub buffered: Cell<bool>,          // In suspect buffer?
    pub trace_fn: fn(...),             // Virtual: trace children
    pub drop_data_fn: fn(...),         // Virtual: drop payload
    pub dealloc_fn: fn(...),           // Virtual: free memory
}

    The three function pointers implement type-erased virtual dispatch — the GC can trace and free any CycleNode<T> without knowing the concrete T at runtime.

    2.2 Per-Actor Isolation (Orí)

    IfaGc<T> is !Send and !Sync (gc.rs:62):

    pub struct IfaGc<T: Trace> {
    pub(crate) ptr: NonNull<CycleNode<T>>,
    _marker: PhantomData<*mut ()>, // Explicitly !Send and !Sync
}

    This enforces the Orí (head) per-actor heap invariant at the type-system level. Every actor thread has its own suspect buffer and heap. No GC pointer ever crosses an actor boundary.

    Cross-actor transfer is always deep copy. The actor.rs:102-115 send() method serializes IfaValue → Vec<u8> via bincode before sending to the channel. The receiver deserializes and allocates fresh IfaGc handles in its own Orí heap.

    3. Bacon-Rajan Algorithm

    gc.rs:202-303. The collector runs in four passes:

    PassFunctionWhat it does
    1. Mark Rootsmark_grayPurple nodes (decref suspects) → Gray. Traces children, decrementing their tracing_rc.
    2. ScanscanGray nodes with tracing_rc > 0 → Black (reachable externally). Others → White (cyclic garbage candidates).
    3. Collect Whitecollect_whiteWhite nodes → Red (condemned). Recursively collects the entire cyclic garbage subgraph.
    4. FreeinlineCall drop_data_fn then dealloc_fn on every Red node. Overcounted strong refs are NOT double-freed because Drop::drop returns early for Color::Red.

    All traversal uses explicit worklists, not recursion — no stack overflow for deep cycles (gc.rs:207, 228, 240, 246).

    3.1 Drop Path

    gc.rs:131-161. The Drop implementation has two paths:

    • Fast path (prev == 1): Strong count hits zero. If the node is not buffered, free it immediately. 95%+ of allocations are acyclic and take this path — no GC overhead.
    • Slow path: Strong count > 0. If the node is Black (was reachable), turn it Purple and push to the thread-local suspect buffer.
    • Red guard: If the node is already Red (being dismantled by the collector), return immediately — prevents recursive dismantling.

    3.2 Trigger Point

    vm.rs:893-895. The GC runs every 1024 VM ticks:

    self.ticks = self.ticks.wrapping_add(1);
if self.ticks % 1024 == 0 {
    ifa_types::gc::collect_cycles();
}

    Also triggered at Drop for IfaVM to drain any remaining suspects before teardown.

    4. SendableValue — Thread Boundary

    The IfaGc cycle collector is !Send by design. All cross-thread communication must go through a serialization boundary. The actor system solves this with ActorMsg::SerializedValue(Vec<u8>) (actor.rs:78).

    The pattern applies everywhere IfaValue crosses a thread boundary:

    // ── VM Thread ──┐                    ┌── Hardware Thread ──
//                 │                    │
//  IfaValue       │   bincode::serialize│   deserialize
//  → serialize() ─┼───────────────────→│   → process
//                 │                    │   → serialize
//  IfaValue       │   deserialize      │   ↑
//  ← deserialize ─┼────────────────────│←──┘
//                 │                    │
    Hardware workers never hold IfaGc pointers. Storage, GPU, and network threads work with serialized Vec<u8> exclusively. See crates/ifa-std/src/hardware/storage.rs for the canonical pattern.

    Variants that cannot be serialized (Fn, Closure, Actor, Future) are rejected at serialization time (value_union.rs:624-629) — a compile-time-like error that prevents accidental cross-thread leakage of GC pointers.

    5. Ebo Epochs

    The ebo { ... } language keyword creates a scoped memory epoch (ast.rs:204-210). When the block exits, the VM triggers a targeted GC sweep for allocations within that epoch.

    See Ebo documentation for the user-facing API.

    6. Key Invariants

    1. Every actor has its own heap. IfaGc is !Send — no GC pointer crosses thread boundaries.
    2. Cross-actor transfer is always deep copy. Serialize at the sender, deserialize at the receiver. Fresh IfaGc handles in the receiver's heap.
    3. 95%+ allocations bypass the collector. The prev == 1 fast path in Drop frees acyclic allocations immediately.
    4. The cycle collector is the fallback. Epoch reclamation (ebo) is the primary memory management strategy. The Bacon-Rajan collector handles long-lived cyclic state that escapes epochs.
    5. Bytecode is safe to share. The constant pool contains only primitives and strings — never IfaGc pointers. unsafe impl Send/Sync at bytecode.rs:84-85 is correct but must be reviewed if the constant pool gains closure support.
    6. #![forbid(unsafe_code)] was removed from ifa-types. The GC module (gc.rs) uses unsafe for pointer manipulation. The module is tagged #[allow(unsafe_code)] at lib.rs:36. All other modules remain safe.
