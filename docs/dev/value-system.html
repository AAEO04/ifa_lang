    2. Small-Int Pool

    value_union.rs:165-178. Integers 0–255 are cached in a OnceLock<[IfaValue; 256]>. IfaValue::int(n) returns a clone of the pre-allocated cell for values in range, avoiding unnecessary allocations for small integers.

    pub fn int(n: i64) -> Self {
    static SMALL_INT_POOL: OnceLock<[IfaValue; 256]> = OnceLock::new();
    if (0..=255).contains(&n) {
        let pool = SMALL_INT_POOL.get_or_init(|| {
            std::array::from_fn(|i| IfaValue::Int(i as i64))
        });
        return pool[n as usize].clone();
    }
    IfaValue::Int(n)
}

    5. Ikin Constant Pool

    vm_ikin.rs — the VM's runtime interned string table.

    • Stores strings as Arc<str> in a flat Vec
    • ASCII fast path: returns byte length directly without lookup
    • Access by consult_string(idx: usize) -> Option<&Arc<str>> with a bytecode_to_ikin: Vec<u32> mapping
    • Loaded from bytecode at each execute() call (vm.rs:539, ikin load at vm.rs:547)
    • In the compiler, strings are deduped via string_index: HashMap<String, u16> (ifa-compiler/src/lib.rs:31)

    6. Send + Sync Design

    IfaValue is no longer Send — heap variants (List, Map, Closure, Upvalue) use IfaGc<T> which is !Send (per-actor heap isolation). Cross-thread communication goes through serialization (bincode) instead.

    • Actor messages are serialized Vec<u8> — always deep copy
    • IfaShared uses Arc<RwLock> / DashMap for VM infrastructure, never for user-visible IfaValue
    • Scalar variants (Null, Bool, Int, Float, Str) are still trivially Send
    • Bytecode constant pool is unsafe impl Send/Sync — only primitives and strings, no IfaGc pointers

    7. IfaValueSurrogate — Serialization Bridge

    IfaValueSurrogate (value_union.rs:597) is the intermediate representation between IfaValue and bincode bytes. Used by both the yanda deep-copy transfer and the Storage persistence engine.

    enum IfaValueSurrogate {
    Null,
    Bool(bool),
    Int(i64),
    Float(f64),
    Str(String),
    List(Vec<IfaValue>),           // values remain as IfaValue for recursive serialization
    Map(HashMap<String, IfaValue>),
    Set(HashSet<IfaValue>),
}

    Conversion is a two-step process:

    1. IfaValue → IfaValueSurrogate — Replaces GC-backed heap types (IfaGc<Vec>, IfaGc<HashMap>, IfaGc<HashSet>) with their owned equivalents. Non-serializable variants (Fn, Closure, Actor, Future) raise an error.
    2. IfaValueSurrogate → bincode bytes — Standard serde serialization to Vec<u8>.

    Deserialization goes the reverse direction, allocating fresh IfaGc handles on the receiving actor's heap. The Set variant was added specifically to enable cross-cutting serialization between yanda and Storage — if a value can be sent across actors, it can also be persisted to disk.

    8. IfaValue — Single Canonical Definition

    The canonical IfaValue enum lives in value_union.rs. The legacy value.rs re-export shim in ifa-vm has been deleted — all imports now use ifa_types::IfaValue directly.
