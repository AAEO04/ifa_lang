    2. Entry Points

    Compiler::compile(program) (lib.rs:97):

    pub fn compile(mut self, program: &Program) -> IfaResult<Bytecode> {
    for stmt in &program.statements {
        self.compile_statement(stmt)?;
    }
    self.emit(OpCode::Halt);
    self.bytecode.exports = collect_exports(program);
    Ok(self.bytecode)
}

    4. Optimizations (Current)

    The compiler has no full optimization pipeline — no dead code elimination or peephole optimization. Several targeted optimizations exist:

    4a. Constant Folding

    lib.rs:1775. fold_expression() evaluates binary operations on literal integers, floats, booleans, and strings at compile time. Also folds Odù method calls with constant arguments (E6: Constant Divination, lines 1937-2036), including Obara.fikun/add, Ika.gigun/len/upper/lower.

    4b. Tail Call Optimization

    lib.rs:592-617. When a return statement wraps a direct function call (return f(x)), the compiler emits:

    LoadGlobal/Local/Upvalue <func>  // push function
[compile args...]                 // push arguments
TailCall <arg_count>             // VM reuses current frame
// Instead of: Call + Return      // which would push+pop a frame

    4b. Constant Inlining

    lib.rs:1213-1216. When an Identifier expression matches a const declaration, the compiler inlines the original expression AST at the use site (macro-like substitution, not compile-time evaluation):

    Expression::Identifier(name) => {
    if let Some(expr) = self.constants.get(name).cloned() {
        self.compile_expression(&expr)?;  // inline the const's AST
        return Ok(());
    }
    // else: resolve as local/upvalue/global
}

    4c. Static Odu Method Resolution (CallOduFast)

    lib.rs:1571-1587. When a domain method call has both a statically-known domain and method name, the compiler resolves them to integer IDs via resolve_method_id() and emits CallOduFast instead of CallOdu:

    // CallOdu:  string-based, runtime HashMap lookup
CallOdu <domain_id:u8> <method_name:string_idx:u16> <arg_count:u8>

// CallOduFast: integer-based, direct dispatch (zero string overhead)
CallOduFast <domain_id:u8> <method_id_hi:u8> <method_id_lo:u8> <arg_count:u8>
// method_id encoding: high byte = domain_id, low byte = method index within domain

    The method ID mapping is maintained in ifa-types/src/methods.rs (217 lines). CallOduFast is handled by the VM via OduRegistry::call_fast() (native.rs:63).

    5. String Deduplication

    lib.rs:126-137. Every unique string literal is emitted exactly once into the bytecode string pool. string_index: HashMap<String, u16> maps content to index. Subsequent uses of the same string reuse the existing index.

    fn emit_string(&mut self, s: &str) {
    let idx = if let Some(&existing) = self.string_index.get(s) {
        existing                          // reuse existing index
    } else {
        let idx = self.bytecode.strings.len() as u16;
        self.bytecode.strings.push(s.to_string());
        self.string_index.insert(s.to_string(), idx);
        idx
    };
    self.emit_byte((idx & 0xff) as u8);   // little-endian u16
    self.emit_byte((idx >> 8) as u8);
}

    6. Import Compilation

    lib.rs:700-737. Two modes:

    • Std imports (is_std == true): binds __odu_fn__:<domain>:<method> markers for the 16 fixed Odù domains. No Import opcode emitted.
    • External imports (is_std == false): emits OpCode::Import with the module path. With named imports, emits Dup + PushStr + GetIndex to extract specific bindings from the module object.
