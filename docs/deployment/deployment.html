Deployment Targets

Multi-Platform Runtime Architecture

Overview

Ifa-Lang supports multiple deployment targets through a unified codebase with platform-specific optimizations. The compilation pipeline (parser from ifa-parser, compiler from ifa-compiler, bytecode VM from ifa-vm) adapts to different environments.

Native Deployment (ifa-cli)

The native CLI provides the complete Ifa-Lang experience with all features enabled. Built on IfaVM (bytecode VM with step() dispatch loop), Opon epoch memory system, and IfaValue (32-byte tagged union, SSO up to 21 bytes, Arc<Mutex>/Arc<str>).

Installation

git clone https://github.com/ifa-lang/ifa-lang
cd ifa-lang
cargo install --path crates/ifa-cli

# Or install via
cargo install ifa-cli --git https://github.com/ifa-lang/ifa-lang

Feature Flags

Granular feature flags: native, parallel (rayon), sysinfo, gpu (wgpu), persistence, network (ureq), audio (rodio), crypto, ml, js, python, native_ffi, wasm.

WebAssembly Deployment (ifa-wasm)

WASM target with browser bindings via wasm-bindgen.

cargo build --target wasm32-unknown-unknown --package ifa-wasm

Embedded Deployment (ifa-embedded)

no_std runtime using ifa-vm with default-features=false, heapless bounded collections. Targets: esp32, stm32, rp2040.

Two tiers: Tier 0 (no_std, no_alloc, stack-only) and Tier 1 (IoT with alloc feature).

See Embedded Deployment for full details.

Sandboxed Deployment (ifa-sandbox)

Capability-based security model using the Ofun enum: ReadFiles, WriteFiles, Network, Execute, Environment, Time, Random, Stdio, Crypto, Bridge. CapabilitySet is passed to interpreter/VM for runtime enforcement.

See Sandbox Guide for full details.

Feature Flags Reference

Granular feature flags are defined per-crate in their Cargo.toml files. Key flags:

  • parallel — Rayon-based parallel iterators (CPU domain)
  • gpu — WGPU GPU compute (GPU domain)
  • persistence — Storage domain with OduStore
  • sysinfo — System information (Sys domain memory/uptime)
  • network — Ureq HTTP client (Otura domain)
  • crypto — Cryptographic operations (Irete domain)
  • backend — Backend stack (Otura HTTP)
  • game — Terminal UI (Ose domain)
