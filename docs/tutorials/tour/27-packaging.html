Building & Packaging

Compiling to native binaries and managing projects with Oja

Native Builds

Use ifa build to transpile Ifá-Lang to Rust and compile a native binary:

Build Command 
# Build a native binary (optimized)
ifa build app.ifa -o myapp

# Build with domain features
ifa build app.ifa --backend
ifa build app.ifa --frontend
ifa build app.ifa --game
ifa build app.ifa --crypto
ifa build app.ifa --iot
ifa build app.ifa --fullstack

# Specify output path
ifa build app.ifa --output ./dist/myapp

Project Management with Oja

ifa oja is the built-in package manager:

Oja Commands 
# Initialize a new project
ifa oja init my-app
ifa oja init my-app --domain basic
ifa oja init my-app --domain fullstack

# Add a dependency
ifa oja add https://github.com/user/package
ifa oja add ../local-pkg

# Remove a dependency
ifa oja remove package-name

# Install all dependencies from lockfile
ifa oja install

# Build the project
ifa oja build
ifa oja build --release

# Run the project
ifa oja run

# Run tests
ifa oja test

# List installed dependencies
ifa oja list
ifa oja tree  # show dependency tree

Ifa.toml Configuration

The project manifest file defines your project's metadata and dependencies:

Ifa.toml 
[package]
name = "my-app"
version = "0.1.0"
description = "An Ifá-Lang application"

[features]
backend = ["ifa-std/backend"]
crypto = ["ifa-std/crypto"]
game = ["ifa-std/game"]

[dependencies]
http = { git = "https://github.com/example/http.ifa" }
json = { path = "../json-lib" }

Dependency Resolution

Oja uses SemVer for version resolution and generates a lockfile for reproducible builds:

Audit & Update 
# Check for vulnerabilities in dependencies
ifa oja audit

# Re-resolve dependencies (update lockfile)
ifa oja update

# Upgrade the CLI itself
ifa oja upgrade

Publishing Packages

Publish 
# Search the registry
ifa oja search http

# Publish a package (creates a Git tag)
ifa oja publish

Searching for Packages

Search 
# Search the package registry
ifa oja search web
ifa oja search crypto
ifa oja search database
Transpilation Pipeline

ifa build works by: (1) parsing the .ifa source, (2) transpiling AST to Rust via ifa-transpiler, (3) generating Cargo.toml and main.rs, (4) running cargo build --release. The result is a standalone native binary with no runtime dependency.
