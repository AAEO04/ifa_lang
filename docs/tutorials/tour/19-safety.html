Safety & Directives

Taboo, unsafe blocks, and memory directives

Taboo: Domain Restrictions

taboo / èèwọ declares that one domain is forbidden from calling another. This is enforced at compile time by Babalawo:

Taboo Declaration 
// Ogbe must not call Odi (separation of concerns)
èèwọ: Ogbe -> Odi;

// Okanran must not call Otura
taboo: Okanran -> Otura;
// Ogbe must not call Odi (separation of concerns)
taboo: Ogbe -> Odi;

// Okanran must not call Otura
taboo: Okanran -> Otura;
Compile-Time Only

Taboo declarations are compile-time directives checked by ifa babalawo and ifa check. They produce zero runtime overhead. Violations are reported as diagnostics during static analysis.

Unsafe Blocks (Ailewu)

Use ailewu / unsafe for low-level operations like raw pointers. Safety checks happen at static analysis time:

Unsafe Block 
ailewu {
    // Low-level memory operations
    // Bypasses some safety checks
    ayanmo p = &0x4000;
    ayanmo val = *p;
    Irosu.fo("Value: " + val);
}
unsafe {
    // Low-level memory operations
    // Bypasses some safety checks
    let p = &0x4000;
    let val = *p;
    Irosu.println("Value: " + val);
}
Safety Warning

Unsafe blocks disable certain runtime safety checks. Use them only when you need direct memory access or hardware interactions. Always validate pointers and bounds yourself.

Memory Directives (Opon)

The #opon directive sets the memory configuration for your program. Think of it as declaring the calabash size. Opon controls slot capacity, stack depth, and frame nesting limits — not GC frequency (see Opon Reference):

Opon Sizes 
// Tiny memory footprint (embedded targets)
#opon kekere;

// Default size
#opon arinrin;

// Large heap allowed
#opon nla;

// Unlimited memory
#opon ailopin;
Size Meaning Use Case
kekere Small Embedded (ESP32, STM32, RP2040)
arinrin Medium Default / general purpose
nla Large Heavy data processing
ailopin Unlimited No memory restrictions

Combining with Ebo

Use opon with ebo for scoped memory management:

Memory Scoping 
#opon nla;
ebo "big-computation" {
    // Large memory operations
    // Memory is managed within this epoch
}
