    36. Type System Deep Dive

    Low-level types, Ptr/Ref/RefMut, Array, Void, and the effects system

    Beyond the dynamic types (Int, Float, Str, Bool, List, Map), Ifá-Lang has an optional static type system for performance-critical and FFI code.

    1. Sized Integer Types

    When you need exact bit widths — for networking, binary formats, or embedded targets:

    // Signed integers
ayanmo a: I8 = -128;
ayanmo b: I16 = -32768;
ayanmo c: I32 = -2_147_483_648;
ayanmo d: I64 = -9_223_372_036_854_775_808;

// Unsigned integers
ayanmo e: U8 = 255;
ayanmo f: U16 = 65535;
ayanmo g: U32 = 4_294_967_295;
ayanmo h: U64 = 18_446_744_073_709_551_615;

    2. Sized Float Types

    ayanmo x: F32 = 3.14;  // 32-bit float (single precision)
ayanmo y: F64 = 3.14;  // 64-bit float (double precision, default)

    3. Ptr, Ref, RefMut

    Pointer types for low-level memory access. These are primarily used in FFI and embedded contexts:

    // Ptr — opaque pointer (for FFI)
ayanmo handle: Ptr = get_ffi_handle();

// Ref — immutable reference
ayanmo data: Ref(Str) = &greeting;

// RefMut — mutable reference
ayanmo buffer: RefMut(List) = &mut items;
    Safety: Ptr operations are unchecked. Use ailewu / unsafe blocks when working with raw pointers.

    4. Array Type

    The Array type is a fixed-size, stack-allocated sequence of elements. Unlike List, the size is known at compile time:

    // Array of 5 integers
ayanmo buffer: Array { element: U8, size: 256 } = init_buffer();

// Array access
ayanmo first = buffer[0];

    5. Void Type

    Void represents the absence of a value. Used as a return type for functions that perform side effects without returning data:

    ese log_message(msg: Str) -> Void {
    Irosu.fo(msg);
    // No return value needed
}
    Note: Ifá-Lang also supports nil / null / ofo as the unit value. Void is for strict type annotations.

    6. The Effects System

    Functions can declare their side effects. This is used by Babalawo for static analysis:

    // Pure function — no side effects
ese add(a, b) -> Pure {
    pada a + b;
}

// Async function
ese fetch_data(url) -> effects Async {
    ayanmo response = reti Otura.gba(url);
    pada response;
}

// Network effect
ese send_request(url) -> effects Network {
    ayanmo result = Otura.gba(url);
    pada result;
}

// File I/O effect
ese read_config() -> effects FileIO {
    ayanmo data = Odi.ka("config.ifa");
    pada data;
}

// State mutation
ese increment() -> effects State {
    counter = counter + 1;
    pada counter;
}

// Impure (FFI / opaque)
ese call_native() -> effects Impure {
    // Calls into C/FFI
}

    Effects can be combined:

    // Multiple effects
ese read_and_send() -> effects FileIO, Network {
    ayanmo data = Odi.ka("/tmp/data")?;
    ayanmo result = Otura.ran("https://api.example.com", data)?;
    pada result;
}

    The default effect (when undeclared) is Pure. Babalawo warns when a function with undeclared effects performs side-effect operations.
