Modules & Imports

Organizing code with modules

Importing Standard Library Domains

Use iba / import to bring in module functionality:

Basic Import 
// Import the entire Irosu domain
iba std.irosu;

Irosu.fo("Hello from Irosu domain!");

// Import specific methods
iba { fo, so } from std.irosu;
fo("Direct method call");
// Import the entire Irosu domain
import std.irosu;

Irosu.println("Hello from Irosu domain!");

// Import specific methods
import { println, print } from std.irosu;
println("Direct method call");

Importing Multiple Domains

Multiple Imports 
iba std.ogbe;
iba std.ogunda;
iba std.obara;

// Now all three domains are available
ayanmo items = [10, 20, 30];
Irosu.fo("Count: " + Ogbe.iye_ohun(items));
Ogunda.fi(items, 40);
Obara.apapo(items);

Importing Local Modules

Import your own .ifa files as modules:

Local Modules 
// In helpers.ifa:
isodale greet(name) {
    Irosu.fo("Hello, " + name + "!");
}

// In main.ifa:
iba { greet } from helpers;

greet("World");  // "Hello, World!"

Module Search Path

Ifá-Lang resolves modules in this order:

  1. Current directory (relative path)
  2. Standard library (std.* prefix)
  3. Installed packages (via ifa oja)

Exporting from Modules

Functions defined at the top level are automatically exported. Use const for shared constants:

Exports 
// In math.ifa:
const PI = 3.14159;

isodale circle_area(radius) {
    PI * radius * radius
}

// In app.ifa:
iba { PI, circle_area } from math;

Irosu.fo("Area: " + circle_area(5));
Module Hygiene

Named imports (import { a, b } from mod) are preferred over glob imports as they make dependencies explicit and avoid name collisions. Each .ifa file is a module.

Package Manager (Oja)

For third-party packages, use ifa oja (see Lesson 27: Building & Packaging):

Oja Workflow 
# Create a new project
ifa oja init my-app

# Add a dependency
ifa oja add https://github.com/user/package

# Install all dependencies
ifa oja install
