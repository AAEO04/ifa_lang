Concurrency & Actors

Async, parallelism, and actor model with Osa

Osa: The Odù of Movement

Osa governs async operations, concurrency, and the actor model. Feature-gated behind async_runtime. Osa uses tokio under the hood for async runtime and OS threads for actor isolation.

Async Spawning

Use Osa.sa()/spawn() to run a task concurrently:

Async Task 
isodale task(name, duration) {
    Irosu.fo(name + " starting");
    daro Osa.sun(duration);
    Irosu.fo(name + " done");
}

// Spawn two tasks concurrently
ayanmo t1 = Osa.sa({ -> task("Task 1", 2000) });
ayanmo t2 = Osa.sa({ -> task("Task 2", 1000) });

// Wait for both (using timeout)
daro Osa.pelu_akoko(t1, 5000);
daro Osa.pelu_akoko(t2, 5000);
fn task(name, duration) {
    Irosu.println(name + " starting");
    await Osa.sleep(duration);
    Irosu.println(name + " done");
}

// Spawn two tasks concurrently
let t1 = Osa.spawn({ -> task("Task 1", 2000) });
let t2 = Osa.spawn({ -> task("Task 2", 1000) });

// Wait for both (using timeout)
await Osa.pelu_akoko(t1, 5000);
await Osa.pelu_akoko(t2, 5000);

Actors (Isolated VMs)

Actors are fully isolated VM instances running on their own OS thread. They communicate via message passing:

Actor Pattern 
// Define the actor's message handler
isodale counter_handler(msg) {
    yan (msg) {
        "increment" => Irosu.fo("Counter: +1");
        "reset"     => Irosu.fo("Counter: reset");
        _           => Irosu.fo("Unknown: " + msg);
    }
}

// Spawn the actor (starts a new VM thread)
ayanmo actor = Osa.egbe(counter_handler);

// Send messages to the actor
Osa.ran(actor, "increment");
Osa.ran(actor, "increment");
Osa.ran(actor, "reset");

// Actors are fully isolated - no shared state
// Each actor has its own memory space
// Define the actor's message handler
fn counter_handler(msg) {
    match (msg) {
        "increment" => Irosu.println("Counter: +1");
        "reset"     => Irosu.println("Counter: reset");
        _           => Irosu.println("Unknown: " + msg);
    }
}

// Spawn the actor (starts a new VM thread)
let actor = Osa.spawn_actor(counter_handler);

// Send messages to the actor
Osa.send(actor, "increment");
Osa.send(actor, "increment");
Osa.send(actor, "reset");

// Actors are fully isolated - no shared state
// Each actor has its own memory space

Parallel Processing (CPU Domain)

For data-parallel operations (see Lesson 11):

CPU Parallel 
// Parallel map
ayanmo numbers = [1, 2, 3, 4, 5, 6, 7, 8];
ayanmo squared = Cpu.par_map(numbers, { x -> x * x });

// Parallel reduce
ayanmo sum = Cpu.par_reduce(numbers, { a, b -> a + b });

// Configure thread pool
Cpu.configure("threads", 4);
Cpu.configure("workgroup", 128);

Yielding

Yield 
// Yield to the scheduler (cooperative multitasking)
Osa.jeki();

// Yield for a specific duration
jowo 100;  // yield for 100ms
When to Use What

Cpu.par_map/reduce — data parallelism (pure computation on large lists).
Osa.sa() — async I/O tasks (network, file, timers).
Osa.egbe() — actor model for state isolation and message passing.
