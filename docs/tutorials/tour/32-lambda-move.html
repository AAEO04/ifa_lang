    32. Lambda, Closures & Move

    Anonymous functions, upvalue capture, and ownership transfer

    Beyond named functions, Ifá-Lang supports anonymous functions (lambdas) that capture variables from their enclosing scope, and explicit ownership transfer with yanda / move.

    1. Lambda Syntax

    A lambda is a function without a name. Use any function keyword followed by parameters and a body:

    // Simple lambda assigned to a variable
ayanmo double = fn(x) { x * 2 };
Irosu.fo(double(5));  // 10

// Yoruba spelling
ayanmo ilopo = ese(x) { x * 2 };

// Multi-parameter lambda
ayanmo add = fn(a, b) { a + b };

    Lambdas are first-class — you can pass them to domain methods:

    ayanmo items = [1, 2, 3, 4, 5];

// Lambda as mapper
ayanmo doubled = Ogunda.yi_pada(items, fn(x) { x * 2 });
Irosu.fo(doubled);  // [2, 4, 6, 8, 10]

// Lambda as predicate filter
ayanmo evens = Ogunda.yan(items, fn(x) { x % 2 == 0 });
Irosu.fo(evens);  // [2, 4]

    2. Closures — Capturing Upvalues

    A lambda that refers to variables from its enclosing scope is a closure. The captured variables are called upvalues:

    ese make_counter(start) {
    ayanmo count = start;
    // This lambda captures 'count' from the enclosing scope
    pada fn() {
        count = count + 1;
        pada count;
    };
}

ayanmo counter = make_counter(10);
Irosu.fo(counter());  // 11
Irosu.fo(counter());  // 12
Irosu.fo(counter());  // 13

    The inner lambda captures count as an upvalue. Each call to make_counter creates a fresh count:

    ayanmo a = make_counter(0);
ayanmo b = make_counter(100);
Irosu.fo(a());  // 1
Irosu.fo(a());  // 2
Irosu.fo(b());  // 101  — independent from a

    3. Move — Ownership Transfer

    Use yanda / move to transfer ownership of a value. This is primarily used when sending values across actor boundaries, but can also be used to prevent aliasing within a single thread:

    ayanmo original = [1, 2, 3];

// Move ownership to a new variable
ayanmo moved = yanda original;
// original is Null at runtime (MoveLocal opcode clears the slot)
// Babalawo flags any use-after-move as a compile error

    The MoveLocal opcode (0x1F) clears the source slot to Null at runtime for identifier moves. For cross-actor transfer, the value is serialized and deserialized on the receiver's heap — guaranteeing full ownership with no shared mutable state.

    // Practical: send data to an actor
ajose worker {
    ibeere: fn(data) {
        Irosu.fo("Got: " + Ogunda.iwon(data) + " items");
    }
}

ayanmo large_data = Ogunda.seda(1000, fn(i) { i });
yanda large_data to worker;
// worker processes its own copy

    4. Move in Closures

    When a closure captures a variable you want to transfer ownership of, use move before the lambda:

    ayanmo handle = Otura.de(":8080");

// Move handle into the closure
ayanmo task = fn() {
    // handle is captured by reference
    ayanmo conn = Otura.gba_handle(handle);
    Irosu.fo("Accepted connection");
};

// Without move, handle is borrowed
// With move, ownership transfers into the closure
