    38. Extended Domains

    Coop (FFI), Opele, Gpu, Storage, and Sys

    Beyond the 16 canonical Odù, Ifá-Lang has extended domains for infrastructure, FFI, and compound operations.

    1. Coop — FFI Bridge

    Coop (also accessible as Ffi or Bridge) provides foreign function interface capabilities. It lets you call into C, Rust, or other languages:

    // Call a C function
ayanmo result = Coop.call("c_function_name", [arg1, arg2]);

// Load and call from a shared library
ayanmo lib = Coop.load("libmylib.so");
ayanmo version = Coop.call_in(lib, "get_version", []);

// Memory operations
ayanmo buf = Coop.alloc(1024);
Coop.copy(src, buf, 100);
Coop.free(buf);
    Safety: FFI calls can crash the VM if misused. Wrap Coop calls in ailewu / unsafe blocks when possible.

    Coop requires the native_ffi feature and the Bridge capability:

    // Check capability first
ti (Ofun.le("Bridge")) {
    ayanmo result = Coop.call("math_pow", [2, 10]);
} bibeko {
    Irosu.kigbe("FFI not available");
}

    2. Opele — Compound Domain Oracle

    Opele (the Oracle) handles compound domain operations and divination patterns. It is a meta-domain that combines multiple Odù:

    // Get the combined meaning of two domains
ayanmo meaning = Opele.ibo(Ogbe, Oyeku);

// Resolve a compound Odù pattern
ayanmo pattern = Opele.resolve("ogbe-oyeku");

// Query the oracle for guidance
ayanmo advice = Opele.iboo("Should I deploy?");

    Opele is primarily used in tooling, not in application code. The Babalawo static analyzer uses it for compound type analysis.

    3. Gpu — Compute Domain

    Gpu provides access to GPU compute via wgpu. It is gated behind the gpu feature flag:

    // Check GPU availability
ayanmo available = Gpu.is_available();

// Get GPU info
ayanmo info = Gpu.info();
Irosu.fo(info);  // { name: "NVIDIA RTX 4090", memory: 24564 }

// Execute compute shader
ayanmo input = [1.0, 2.0, 3.0, 4.0];
ayanmo output = Gpu.compute("shader.wgsl", input);

// Buffer operations
ayanmo buf = Gpu.alloc_buffer(1024);
Gpu.write_buffer(buf, input);
ayanmo result = Gpu.read_buffer(buf);

    GPU support is optional and platform-dependent. Use Ofun.le("Compute") to check availability at runtime.

    4. Storage — Key-Value Persistence

    Storage (also Kv / Db) provides persistent key-value storage backed by an append-only log. All operations are async (return Future):

    // Open a store (returns Future — await with reti)
ayanmo store = reti Storage.open("data.ifas");

// Store a value
reti Storage.set(store, "username", "john_doe");

// Retrieve
ayanmo user = reti Storage.get(store, "username");  // "john_doe"

// Delete
reti Storage.delete(store, "username");

// Compact the append-only log
reti Storage.compact(store);

    Storage persists to disk via OduStore. The backend is configurable (default: local file, with network DB options via features). Values are serialized using the same bincode path as yanda — most IfaValue variants are supported, including the Set type.

    5. Sys — Kernel/OS Interface

    Sys extends Ogbe with kernel-level operations. It provides lower-level system access:

    // System information
ayanmo os = Sys.os();        // "linux"
ayanmo arch = Sys.arch();    // "x86_64"
ayanmo hostname = Sys.hostname();
ayanmo uptime = Sys.uptime();

// Process management
ayanmo pid = Sys.pid();
Sys.kill(pid, 9);  // Send SIGKILL

// Memory info
ayanmo mem = Sys.memory();
Irosu.fo(mem);  // { total: 16777216, free: 8388608, used: 8388608 }

    Sys requires the sysinfo feature. All Sys operations require the Environment capability.
