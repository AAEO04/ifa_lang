Security & Capabilities

Deny-by-default capability security model

Ifá-Lang Security Model

Ifá-Lang uses a deny-by-default capability model. Programs start with zero permissions. Capabilities must be explicitly granted via CLI flags or the Ofun domain. This prevents unauthorized access to files, network, or system resources.

Capability Types

ReadFiles--allow-readRead files from disk
WriteFiles--allow-writeWrite files to disk

Checking Capabilities at Runtime (Ofun)

Ofun Capability Checks 
// Check if a capability is granted
ti (Ofun.le("read")) {
    ayanmo data = Odi.ka("file.txt");
    Irosu.fo(data);
} bibeko {
    Irosu.fo("No read permission");
}

// List all granted capabilities
ayanmo caps = Ofun.awon_agbara();
Irosu.fo(caps);  // ["Stdio", "ReadFiles", ...]

// Drop a capability (can only reduce, never add)
Ofun.ju("network");

// Check again after revoking
ti (Ofun.le("network")) {
    Irosu.fo("Network available");
} bibeko {
    Irosu.fo("Network revoked");
}
// Check if a capability is granted
if (Ofun.can("read")) {
    let data = Odi.ka("file.txt");
    Irosu.println(data);
} else {
    Irosu.println("No read permission");
}

// List all granted capabilities
let caps = Ofun.capabilities();
Irosu.println(caps);  // ["Stdio", "ReadFiles", ...]

// Drop a capability (can only reduce, never add)
Ofun.drop("network");

// Check again after revoking
if (Ofun.can("network")) {
    Irosu.println("Network available");
} else {
    Irosu.println("Network revoked");
}

Monotonic Sacrifice (Irreversible)

Ẹbọ: Sacrifice Is Permanent

Once a capability is sacrificed via Ofun.ju(), it is permanently revoked for the lifetime of the VM instance. The capability enters the sacrificed set and no subsequent grant() — explicit or inherited — can restore it. This is the monotonic sacrifice property: the set of available capabilities can only shrink.

Irreversible Revocation 
// Start with full permissions
ayanmo caps = Ofun.awon_agbara();
Irosu.fo(caps);  // includes "read", "write", "network", ...

// Sacrifice network access
Ofun.ju("network");
ti (Ofun.le("network")) {
    Irosu.fo("Network available");
} bibeko {
    Irosu.fo("Network sacrificed");  // this runs
}

// Attempt to re-grant — BLOCKED
// Ofun does not expose a grant() for users because
// sacrifice must be irreversible. Even at the system
// level, a sacrificed capability can never be re-granted:
// Start with full permissions
let caps = Ofun.capabilities();
Irosu.println(caps);  // includes "read", "write", "network", ...

// Sacrifice network access
Ofun.drop("network");
if (Ofun.can("network")) {
    Irosu.println("Network available");
} else {
    Irosu.println("Network sacrificed");  // this runs
}

Structural Coverage

Sacrificing a parent capability blocks all child capabilities it covers:

Path Hierarchy 
// Grant broad read access
// (from CLI: ifa run script.ifa --allow-read /data)

// Sacrifice the root /data
Ofun.ju("read");

// All subpaths are now blocked:
//   Odi.ka("/data/config.json")      ✗ blocked
//   Odi.ka("/data/users/1.profile")  ✗ blocked
//
// The structural check uses canonical paths,
// so /data/../other resolves to /other and is NOT blocked.
Network Domain Hierarchy 
// Grant: --allow-net *.example.com
// Sacrifice: *.example.com
Ofun.ju("network");

// All example.com subdomains are blocked:
//   api.example.com  ✗ blocked
//   app.example.com  ✗ blocked
// But other.com is unaffected.

Inheritance and Child Sandboxes

When a child sandbox is spawned (Osa.egbe), it inherits the parent's sacrificed set before its own granted capabilities. Any capability covered by a parental sacrifice is stripped from the child before it boots:

Child Sandbox Inheritance 
// Parent sacrifices file writes
Ofun.ju("write");

// Spawn a child actor — it inherits the sacrifice
ayanmo worker = Osa.egbe({ ->
    // Odi.ko("log.txt", data) would fail here too
    Irosu.fo("Child has no write permission");
});

// Even if the child was granted write at creation time,
// the inherited sacrifice strips it before execution.
Security Guarantee

Monotonic sacrifice makes the Ẹbọ metaphor a provable security property — not just a convention. A compromised component cannot escalate by re-granting itself or its children a sacrificed capability. Supply-chain attacks that attempt to restore permissions after drop are structurally prevented at the CapabilitySet level.

Architecture: Ofun vs Esu

Ifá-Lang's security has two layers:

Component Role Location
Ofun domain User-facing: string-based capability queries (le("read"), ju("write")) ifa-std/odu/ofun.rs
Esu (Èṣù) Middleware: owns the live capability set, enforces checks via typed Ofun enum ifa-std/esu.rs
Èṣù at the Crossroads

In Yoruba tradition, Èṣù guards the crossroads — the point of decision between paths. In Ifá-Lang, Èṣù stands at every domain method call and judges whether the required capability is held. If not, it blocks the operation before any I/O proceeds. Ofun defines the vocabulary; Èṣù owns the live state and enforces access.

Esu API

The Esu struct wraps a capability set in a thread-safe Arc<Mutex>. It is shared across all domain instances:

Esu Methods 
// Create an Esu with a given capability set
Esu::new(caps)                     // from CapabilitySet
Esu::from_world(caps)              // alias for new()

// Enforce a capability (throws on deny)
esu.enforce_crossroads(&Ofun::ReadFiles { .. }, "odi.ka")

// Soft check (returns bool)
esu.allows(&Ofun::Network { .. })  // true if allowed

// Mutate the world state
esu.ju(cap)                        // revoke (remove) a capability
esu.grant(cap)                     // grant a new capability

// Inspect
esu.world_state()                  // get copy of current CapabilitySet

How Domains Use Esu

Under the hood, every domain that needs I/O holds a clone of the Esu and checks before every operation:

Enforcement in Action 
// When you call Odi.ka("file.txt"):
// The Odi domain internally does:
//
//   esu.enforce_crossroads(
//       &Ofun.ReadFiles("/tmp"),
//       "odi.ka"
//   );
//
// If the capability is missing, you get:
//   "Èṣù blocked 'odi.ka' at the crossroads"

// ---

// The Ofun domain's require_cap! macro does:
//   require_cap!(ofun, "read");
//   // equivalent to:
//   if (!ofun.le("read")) {
//       return Error("Capability 'read' not allowed");
//   }

Sandboxed Ofun Instance

By default Ofun grants all capabilities (for convenience). Use with_capabilities() to create a sandboxed instance with zero permissions:

Sandboxed Ofun 
// Default: all capabilities granted
ayanmo full_ofun = Ofun();  // can read, write, network...

// Sandboxed: start with nothing
ayanmo locked = Ofun.with_capabilities([]);
locked.le("read");     // iro (false)
locked.le("network");  // iro (false)

// Only explicitly granted capabilities work
// This is the deny-by-default model
