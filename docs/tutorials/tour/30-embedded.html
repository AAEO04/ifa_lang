Embedded & IoT

Running Ifá-Lang on microcontrollers

Ifá-Lang Everywhere

Ifá-Lang can run on microcontrollers via the ifa-embedded runtime. It supports ESP32, STM32, and RP2040 targets with a specialized no_std, heapless VM.

Embedded Targets

Target Architecture Memory Use Case
ESP32Xtensa LX6512KB+WiFi/Bluetooth IoT

Memory Configuration

Use #opon kekere for memory-constrained targets:

Embedded Config 
// Small memory footprint for embedded
#opon kekere;

// Minimal embedded program
Irosu.fo("Hello from ESP32!");

// GPIO operations (via hardware abstraction)
ayanmo pin = 2;  // GPIO 2
// pin read/write via HAL traits

Cross-Compilation

Cross Build 
# Build for embedded target
ifa build script.ifa --target esp32
ifa build script.ifa --target stm32
ifa build script.ifa --target rp2040

# Build with IoT features
ifa build script.ifa --iot

# Flash directly to device
ifa flash script.ifa --target esp32 --port /dev/ttyUSB0
ifa flash script.ifa --target rp2040
ifa flash script.ifa --target stm32 --port /dev/ttyACM0

Embedded VM Architecture

The embedded VM is a stripped-down bytecode interpreter:

  • EmbeddedVm: generic const-parameterized VM (stack size, opon size)
  • EmbeddedValue: minimal value type (Null, Bool, Int, Float, Ptr, String, Blob)
  • EmbeddedOpCode: subset of opcodes for constrained devices
  • HAL traits: InputPin, OutputPin, Serial, DelayUs, MmioBus

Hardware Abstraction Layer

HAL Traits 
// These HAL interfaces are implemented per-target:
// - InputPin: is_high(), is_low()
// - OutputPin: set_high(), set_low(), toggle()
// - Serial: write_byte(), read_byte()
// - DelayUs: delay_us(), delay_ms()
// - MmioBus: read(address), write(address, value)

// Usage in embedded Ifá-Lang:
ailewu {
    ayanmo gpio = &0x3FF44004;  // GPIO register
    // Memory-mapped I/O
}

Embedded Workflow

Write standard Ifá-Lang, use #opon kekere for memory constraints, then ifa flash to deploy. The embedded runtime accepts precompiled bytecode and provides hardware abstraction through the MmioBus and GPIO traits.
